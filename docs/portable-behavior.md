# Portable behavior, scalar and text phase (0.3)

This increment implements a bounded, explicitly portable subset of Magritte's existing condition, accessor and string-conversion objects. It does not complete the headless core. The baseline remains upstream `d67f318686b7779aed79416db121e257d1191f2e`; no upstream source or tests were copied. The two ports remain independent headless libraries.

## Implemented and checked

- `MAPluggableCondition` receiver/selector/arguments/index semantics, `MAConjunctiveCondition` (including empty conjunction and short circuit), and `MANegationCondition`. A description stores labelled portable conditions separately from local callback conditions. Kind errors and undefined sentinels skip condition execution; failures retain the label and description identity.
- Finite selector protocol: `isNil`, `notNil`, `isEmpty`, `notEmpty`, `isInteger`, `positive`, `negative`, `even`, `odd`, `=`, `~=`, `<`, `<=`, `>`, `>=`, `between:and:`, `includes:`, `beginsWith:`, `endsWith:`. Unsupported receiver protocols raise an error. `positive` includes zero, matching Smalltalk. Conditions never perform arbitrary messages, compile code or call a VM.
- Dictionary, property, selector, variable, identity, null and chain accessor strategies. Chains read intermediate targets, then write only the terminal target. Native selectors/variables/properties require explicit host bindings; loading a name does not invent reflection. DictionaryModel and Description provide their actual dictionary/property protocols. NativeModel applies strategy records through its binding tables; existing per-description callbacks remain local. AdaptiveModel continues to key values by description identity, as upstream does.
- `MASymbolDescription`, `MAMemoDescription`, `MAPasswordDescription` and `MATokenDescription`. Symbols preserve their type on interchange and have String ancestry/content equality. Password masking is an explicit operation; ordinary string writing does not mask. Tokens default to Array and do not automatically validate elements through their reference. Boolean options and labels are implemented with the upstream fixed aliases and configurable trueString/falseString.
- Number values now include finite IEEE-754 binary64, mixed numeric bounds and equality. Int64/binary64 equality is exact; integer-to-float conversion cannot silently equate an unrepresentable integer. Signed-zero bits survive interchange. Set uniqueness follows numeric equality; option labels still use identity-safe keys, so Integer 1's label does not apply to Float 1.0.
- `MAStringReader` and `MAStringWriter` entry points for the supported strings/symbols, Boolean, decimal numbers, tokens and options. Writers additionally support containers and relations. Empty input returns nil; undefined text matches a prefix; readers do not trim or validate. A single-option label matches a prefix, with ambiguous matches rejected explicitly. Multiple options split on commas and remove one following space; tokens split on any separator and discard empty tokens. Writers retain the upstream separators, including separators surrounding invisible container children.

`portable-v3.json` was created and exported from live GT objects through MCP. `portable-reference.json` records 106 validations, 144 reads, 72 writes, 60 predicate evaluations and five accessor read/write cases. `portable-edges.json` adds finite-float extremes, exact integer parsing, mixed numeric boundaries, password masks, Boolean options/labels, hidden container children and empty token separators. Twenty-four independently authored invalid graphs check unsupported/malformed configuration. `portable-live-methods.json` records 43 inspected method hashes; all match pinned source ignoring whitespace except the number-reader difference below.

Both native test suites import the same fixture. Each edits the sample's number to 2.5, symbol to #next and positive number to 2, then exports. The replay reconstructs real Magritte descriptions, condition/accessor objects and MAAdaptiveModel in GT, validates, tests the compound condition, and exports again. All 23 descriptions and the object match in both directions; the C++ and Swift exports match each other. Replay JSON files are GT MCP requests, not file-in source. No persistent Smalltalk class/method or registered checkout was changed.

## Explicit differences and remaining limits

The installed GT number reader predates pinned upstream's thousandsSeparator removal. The ports follow pinned upstream and remove every separator occurrence. `portable-upstream.json` records the two affected read fixtures (direct Number and single-option fallback); the unmodified GT results remain in portable-reference.json.

The ports deliberately compare Int64/binary64 magnitudes exactly. GT's SmallInteger/Float relational comparison can round the integer: 9007199254740993 is neither less nor greater than Float 9007199254740992.0 there, although equality is false. This VM-dependent ordering is recorded in portable-edges.json, and the portable exact-order policy is explicit in portable-upstream.json. It applies to conditions and numeric ranges. No integer precision is discarded on the wire.

Text number parsing implements `-?digits(.digits)?(e-?digits)?` after removing thousands separators. Integer mantissas with nonnegative exponents are parsed with exact Int64 arithmetic (at most 19 appended zeroes); decimal/negative-exponent forms use finite binary64. Overflows and nonzero underflows to zero fail explicitly. This is not the full Smalltalk NumberParser grammar: arbitrary integers, fractions, radix numbers, scaled decimals, NaN/infinity, dates, durations, times, colors, URLs, classes, files and blocks remain outside this profile. Float display uses shortest-round-trip digits, a mandatory fractional digit and scientific notation at decimal exponent >=6 or <=-5; the checked extremes match GT. This does not certify every Float printing edge on every toolchain.

Conditions support value receivers/constants only; constants containing object references are rejected. There is no arbitrary class lookup, block evaluation, object-message protocol or condition on container models. Local closures, functional defaults and native objects cannot be serialized. Full accessor capability/introspection protocols, composite/delegator/pluggable wire accessors, complete visitor double dispatch, arbitrary display functions, mutable collection identity, editing/mementos and full self-description remain future work. Null accessor comparison tokens are preserved as nil or exactly 16 bytes. Identity/chain value access requires graph-registered targets; a missing/unbound target fails explicitly. Container accessors remain implicit identity on interchange.

String/collection values remain snapshots. Case-insensitive Boolean aliases and option sorting are restricted to ASCII; unsupported non-ASCII comparisons fail. Scalar fallback display supports the documented primitive values; unlabelled complex objects need a later display protocol. Option label fallback uses the option's default display, not reference undefined text; sorting uses reference conversion. Portable condition and accessor forms are checked before a short circuit or visibility flag can conceal an unsupported condition or accessor.

## APIs

C++ exposes `Predicate::evaluate`, `Accessor::read/write`, `readString`, `writeString`, `decode/encodePredicate`, `decode/encodeAccessor` and password helpers on Description. Swift exposes the corresponding native functions/methods. `portableConditions` and optional `accessor` belong to Description. Native binding table keys are `strategyClass:name`; selectors carry separate read and write names. NativeModel/DictionaryModel `resolver` is borrowed in C++ and weak in Swift, and must refer to a living graph when following chains. C++ native object ownership remains with the caller.

Decoding, condition/accessor recursion, comparisons and text conversion enforce configurable byte/depth/item/work limits. Unknown fields/classes/selectors and invalid constants fail explicitly. Graph/1 and graph/2 retain their restricted schemas; only graph/3 adds these forms. Newly constructed graphs default to graph/3, while decoded graphs preserve their format.

Executed validation on macOS arm64: both C++ CTest suites in Debug and with AddressSanitizer/UndefinedBehaviorSanitizer, an external CMake consumer of the installed 0.3 library, and all 19 Swift tests. The two edited graph exports passed the live-GT reconstruction/validation/export comparisons. Other platforms remain unexecuted.
