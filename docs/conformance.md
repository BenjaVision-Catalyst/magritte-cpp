# Conformance and reference evidence

The authoritative fixture location is `conformance/` in [magritte-cpp](https://github.com/BenjaVision-Catalyst/magritte-cpp). `manifest.json` records fixture SHA-256 hashes and the upstream revision. Its immutable Git revision is recorded in the Swift mirror's `conformance-source.json`; fixtures are mirrored into Swift test resources for independent offline builds. Updating fixtures requires reestablishing the reference evidence, updating hashes and deliberately updating the Swift revision lock. There is one expected-results set, not separately maintained native expectations.

- person-v1.json and person-v2.json were created and exported by the running GT image through MCP, using real MAContainer/scalar/MAAdaptiveModel objects.
- reference.json records ten executed scalar cases and separate checks for hidden/read-only/custom undefined values, insertion/priority order, self-described label/required and raw-read versus cached-memento default behavior.
- values.json and invalid-graphs.json are independently authored protocol tests, **not** claims of GT coverage for every wire edge. They exercise exact integer bounds, recursive arrays, Unicode/NUL, unsupported types, bad members/kinds/identities, and explicit failure.
- live-methods.json contains hashes identifying the inspected image methods and notes source divergence from pinned upstream.
- roundtrip-reference.json records GT importing both native-edited Person graphs, validating age=21/email, and reexporting the supported data without semantic changes. The full replay tool requests are in reference-replay.json and roundtrip-replay.json; these are JSON requests for GT MCP, not compiled or file-in source.

The reference operations used CCNativeMcpLease and wrote an external `*-mcp-gate.json` completion marker after lease release. The controller checked that marker outside GT before inspecting output or making another GT call. These were pure Magritte reference operations: no native plugin, Runtime or transport resources were allocated. There is no C++/GT integration run requiring a Runtime owner in this increment. Do not reuse this reference harness to run native integration outside the workspace's isolation/Runtime-owner workflow. Never launch/restart GT or modify a registered checkout externally.

Replay the recorded JSON through GT MCP only, adapting output paths to an authorized independent location. The native outputs required by roundtrip-replay are produced by the C++ conformance executable's optional output argument and by setting MAGRITTE_EXPORT for Swift tests. The reference harness is deliberately limited to the already-validated initial profile and trusted test data; it is not a hardened public Smalltalk importer. No persistent Smalltalk methods/classes were changed, so no image-source recovery or export of new classes was needed. No new gtExample methods were introduced.

The native tests check the GT results rather than inventing expected scalar outcomes from each other. Additional native tests cover property edits via self-description, existing/new objects adopting changed runtime descriptions, generic native/dictionary accessors, local conditions/defaults and rejection of their export, fixed-point graph/value round trips, metadata preservation, malformed/unsupported input, decoding/traversal limits and cycles.

The first increment is executed on macOS arm64 with Apple Clang 21, CMake 4.4.3 and Swift 6.3.3. C++ requires C++17/CMake >=3.20; Swift's package manifest requires Swift >=6.0. Linux and Windows portability have **not** been executed here; neither is a certified platform claim. The core has no UI dependency. C++ vendors the MIT-licensed nlohmann JSON 3.11.3 parser privately and has no network-time build dependency. Swift uses Foundation and has no package dependency on C++ or any other external package.

The relationship phase adds relations-v2.json, relations-reference.json (109 validation/12 option-list cases), relations-invalid.json, relations-live-methods.json, and the relation reference/round-trip replay requests and report. See [relationships.md](relationships.md) for executed behaviors and remaining boundaries. Standalone value fixtures now include graph/2 tags; graph/1 graph fixtures retain their original restricted contract.

The portable phase adds portable-v3.json, portable-reference.json, portable-edges.json, portable-invalid.json, portable-live-methods.json and replay requests for reference/edges/native round trips. portable-upstream.json records the pinned number-reader difference and the explicit exact mixed-number order policy; tests apply those declared policies while retaining original GT results. See portable-behavior.md for counts, boundaries and traceability. C++ `magritte-portable-tests /path/output.json` and Swift `MAGRITTE_PORTABLE_EXPORT=/path/output.json swift test` generate the native inputs for portable-roundtrip-replay.json. Twenty-three descriptions and one edited object are reconstructed, validated and exported through GT for each port.

The editing phase adds editing-scenarios.json, editing-reference.json and its replay (48 scenarios, 201 snapshots, plus a 486-case pinned/live write matrix), self-description-reference.json and its replay (fourteen class-specific metadata graphs and real staged/committed edits), editing-boundaries-reference.json and its replay (unsupported live mutable collection alias evidence), editing-live-methods.json (52 method fingerprints), and editing-roundtrip-reference.json/replay. See editing.md for the eight default-filter differences and the deliberate snapshot boundary; neither is hidden by treating native agreement as reference equivalence. `magritte-editing-tests /private/tmp/magritte-cpp-editing-native.json` and Swift `MAGRITTE_EDITING_EXPORT=/private/tmp/magritte-swift-editing-native.json swift test` produce the replay inputs. GT checked both native metadata-edited graphs, validated their score=8/min=7 values and reexported equivalent graphs. The same lease and post-release marker discipline was used, with no native Runtime resources or persistent Smalltalk source changes.

The 0.5 recursive/composition phase adds composition-reference.json/replay (256 equality cases, twelve composition cases and selective-copy checks), recursive-reference.json/replay (fourteen expanded schemas and three recursive levels), recursive-structural-reference.json/replay (reference edit and four option-text cases), recursive-live-methods.json (37 matching upstream fingerprints and two separately attributed kernel methods), and recursive-roundtrip-reference.json/replay. GT reconstructed and validated both native 47-description metadata graphs and exported equivalent data. Supported class-list, as-is label and SortedCollection snapshot projections are explicit in the fixture and composition.md. Native tests also import the resulting schemas and execute another structural edit. These tests use no persistent image changes or native Runtime resources; existing lease/marker discipline applies.

The 0.6 reflection phase adds class-registry.json (61 real GT Classes), reflection-reference.json/replay (15 description schemas, eight accessor schemas/edits, three condition schemas/evaluations, class validation/text conversion and shared live accessor editing), reflection-live-methods.json (26 matching upstream fingerprints), reflection-invalid.json (native protocol rejection cases), and reflection-roundtrip-reference.json/replay. `magritte-reflection-tests /private/tmp/magritte-cpp-reflection-native.json` and `MAGRITTE_REFLECTION_EXPORT=/private/tmp/magritte-swift-reflection-native.json swift test` generate the inputs. GT reconstructed 54 descriptions and one object from each, validated the application and three metadata schemas, and reexported equivalent graphs. See reflection.md for finite registry/interpreter choices, actual annotation selection and explicit accessor materialization before export. The current suite is five CTest targets and 34 Swift tests.
